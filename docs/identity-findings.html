Prior conversation collapsed several GitHub projects into the same measurements. The identity benchmark uses one implementation per independent signal.

Personality, self-identification, and censorship probes are not identity evidence. They are the first thing a dishonest provider patches and they already produced opposite verdicts on the same stealth model (modelprint README).

Kimi Vendor Verifier as the identity-check template

Primary source: local clone /tmp/Kimi-Vendor-Verifier at 3dad65a, README plus tests/prompt_tokens/test_prompt_tokens.py, tests/k3_features/test_tokenization_groundtruth.py, tests/params/test_params.py, testdata/prompt_token_cases/README.md. Upstream: MoonshotAI/Kimi-Vendor-Verifier.

This is the best process we found for “is this vendor actually serving the claimed model?” It does not work by asking the model who it is. It works by comparing a suspect endpoint to a first-party identity contract:

  1. Official tokenizer + chat template as oracle. Prompt-token cases store expected_prompt_tokens “confirmed against the reference tokenizer; do not guess them.” K3 cases are derived from Moonshot’s internal tokenism golden (totalTokens - len(pendingTokenIds)).
  2. Vendor must report the same usage.prompt_tokens. tests/prompt_tokens/ streams each case and reads stream usage. Accept band is [expected, expected+3] (MAX_PROMPT_TOKEN_OVERCOUNT = 3). Under-count fails; over-count of 4+ fails. This is tokenizer + template identity against the official meter, which is also the billing meter.
  3. Byte-exact groundtruth payload. test_tokenization_groundtruth.py sends a raw JSON string (not re-serialized) whose expected count (539) comes from a local tokenism instance. Comment in source: “the one place where tokenism correctness (not just two-path consistency) is checked.” Currently marked @pytest.mark.skip("skip, not pass") — even Moonshot’s own extra oracle is allowed to lag.
  4. Feature contract unique to the claimed checkpoint. tests/k3_features/ (dynamic tools, response_format, tool_choice, thinking effort) and tests/params/ (immutable temperature/top_p/n defaults and rejections). A cheaper substitute often cannot implement K3’s API surface.
  5. Then capability benches (OCRBench, MMMU, BEAM, DeepSWE) scored against the official row (Moonshot 0.89 / 0.82 / 0.31 / 0.675 at thinking=max). Pre-flight must pass first.

Also record aggregator vs upstream usage: KVV insists on stream-reported usage.prompt_tokens from the vendor path, not an aggregator estimate.

Identity implication for whichllm: copy this shape for every claimed model family. Enrollment = official tokenizer + template + feature contract + official-API behavioral reference. Audit = vendor must match those constants. Capability scores are a serving-fidelity bar, not a unique ID: Fireworks/Together already sit within a few points of Moonshot on OCRBench without that proving they could not be a slightly different K3 build.

False-positive modes inside KVV itself. The +3 prompt-token overcount can hide a nearby template. OCR/DeepSWE proximity can match a different strong coding model. The skipped 539-token oracle means one independent tokenism check is not currently gating CI. Vision cases depend on exact image bytes/dimensions. Stream usage location is Kimi-specific (choices[].usage or top-level).

Tokenizer differential (cloned sources)

Local clones: /tmp/tokenizer-fingerprint HEAD 310c1aa; /tmp/modelprint HEAD 6c27374. White paper: The Tokenizer Is a Fingerprint.

Method (README, one paragraph): hidden chat template adds constant overhead; prompt_tokens(BASE+probe) − prompt_tokens(BASE) is the model’s count for the probe; rank against local Hugging Face tokenizer.json files over 95 strings chosen to separate vocabs (scripts, code, Unicode).

tokenizers/fetch.sh candidates: GLM-4.5, GLM-5.2, glm-4-9b, Qwen3-235B, Qwen2.5-72B, MiMo, DeepSeek-V3.1, Seed-OSS, Yi-1.5, Hunyuan, ERNIE-4.5, MiniMax-M1, Llama-3.1, gpt-oss-120b, Kimi-K2 tiktoken. MiMo is byte-identical to Qwen2.5. GLM-5.3 and Qwen3.8 are not in the zoo even though HF ships tokenizer.json for both.

modelprint’s four tok-* probes (English, Chinese, code, emoji) plus template-offset are the same signal with a one-character baseline and a duplicate-run unstable flag when a router splits hosts. Do not ship both as separate products. Keep: (a) KVV-style official expected constants when the claimed model has a first-party tokenizer; (b) zoo ranking when the claim is unknown/stealth.

Caveats from tokenizer-fingerprint README: vocabulary ≠ operator; specials may be escaped; point-in-time; defeating the fingerprint requires corrupting billing usage.

One-token behavioral identity (arXiv:2607.10252)

Primary: Bruckner, “One Token Is Enough”. Implementation clone: /tmp/llm-fingerprint-detector HEAD 94dc446, src/verdict.ts, src/constants.ts.

  • Battery: 10 tasks × 4 languages (en/ru/zh/ar) = 40 cells; T=1.0; max_tokens=16; reasoning disabled; n≈30 (15 for expensive models).
  • Distance: mean JSD (base 2) over cells with ≥10 valid samples each side.
  • Baselines (paper + Tosea constants): same-model split-half ≈ 0.14; same model other provider median 0.227; different-model median 0.463.
  • Verification EER: 7.3% full 40-cell battery; 10.6% with 8 cells. Tosea verdicts: match ≤0.25, uncertain ≤0.35, else mismatch; insufficient if <4 comparable cells. Split-half warn at 0.25 (backend rotation).
  • Cross-provider AUC 0.880 vs 0.971 same-mix — serving stack moves the signal.
  • Anomaly: writer/palmyra-x5 JSD 0.141 from Qwen3-235B, at the genuine same-model median 0.140.
  • 10 of 34 same-model provider pairs diverged past the 5th percentile of impostors (e.g. Llama-3.2-3B Cloudflare vs Parasail 0.716).
  • Mandatory / hidden reasoning excluded: post-reasoning is a different generative process. 0.76% of census responses still carried a reasoning trace despite disable.
  • System prompt is load-bearing (Tosea README: swapping only the system prompt shifts JSD ≈ 0.44–0.46, impostor magnitude).
  • Gao et al. cited: 11/31 Llama commercial endpoints incompatible with vendor reference weights.

whichllm must never emit a binary “this is model X” from one JSD. The identity benchmark’s default is match / uncertain / mismatch / insufficient, with EER published on the protocol.

TokenPrint (arXiv:2608.08139) — white-box contrast

Wu, Zhao, Chen: top-k vocabulary projections of late hidden states on 250 probes; Jaccard of decoded strings. Requires forward passes / logits, not a chat API. Useful warnings for black-box identity:

  • Output-space similarity does not reliably name the exact parent: R1 distillations retrieve documented base in top-2 but first in only 1/5; Instruct siblings outrank bases.
  • Identical-data models with no shared weights score 0.48 raw — shared corpora look like family.
  • int4 Jaccard 0.82–0.85 vs max cross-model 0.81: aggressive quantization can sit on the identity boundary.
  • Authors refuse standalone proof of training history. Same humility belongs in whichllm tickets.

Kimi K3 vendor benchmark vs DeepSeek and GLM analogs

Kimi (official): MoonshotAI/Kimi-Vendor-Verifier is the first-party vendor-verifier. K3 table compares Moonshot, Fireworks, Baseten, Together, DigitalOcean, Inferact vLLM, Nebius, Modal on OCRBench / MMMU Pro Vision / BEAM(1M) / DeepSWE. Identity-relevant pieces are the pytest contracts (prompt_tokens, params, k3_features, tool schemas), not the leaderboard alone.

DeepSeek — no official analog found. Searched GitHub orgs/products: deepseek-ai vendor/verifier/fingerprint repos via gh search repos --owner=deepseek-ai (empty); web search for official vendor-verifier / prompt_tokens contract. What exists is third-party: karminski/LLM-Vendor-Verfier (cloned /tmp/LLM-Vendor-Verfier) compares tool-call similarity of resellers to deepseek-official (description: “Verify whether the LLM vendor has used quantitative models”). Also FLock-io/Vendor-Verifier (generic tool-call vs baseline). Neither is a DeepSeek-published identity contract with tokenizer goldens. DeepSeek publishes model cards and API docs, not a KVV-style vendor battery.

GLM / Z.ai — no official analog found. Searched zai-org, THUDM, docs.z.ai / Hugging Face cookbooks. Hits are training reward “verifiers” (zai-org/GLM-V glmv_reward math/OCR judges) and vLLM serve flags (--tool-call-parser glm47), plus Z.ai Code Bench as an in-house capability eval on the GLM-5.3 blog — not a third-party serving-identity harness with prompt_token goldens. GLM-5.3 uses the GLM-5.2 base (post-training only), so tokenizer identity cannot separate 5.2 from 5.3.

whichllm should therefore: (1) adopt KVV’s contract shape as the identity reference implementation; (2) for DeepSeek/GLM, construct first-party-derived cases from published tokenizer.json + official API enrollment, and cite the official-gap rather than pretend a vendor-verifier repo exists.

Recommended identity protocol (unlimited tokens, one implementation per signal)

  1. Enroll official API: tokenizer goldens (KVV cases), feature contract, 40-cell one-token fingerprint, dated.
  2. Audit vendor: prompt_tokens vs goldens (fail closed on undercount / >+3); abort if counts unstable across repeats.
  3. JSD vs today’s official fingerprint with match/uncertain/mismatch/insufficient; split-half self-check.
  4. If tokenizer matches but JSD uncertain: capability/context class (size), never personality.
  5. If tokenizer+JSD match and capability collapses: misconfiguration until official serve flags (template, think-mode, tool parser, effort) have been replayed. Do not call that a swap.
  6. Stack DNA (errors/headers, Anthropic Messages JSON, msg_ vs chatcmpl-) only to name the wrapper, not the weights. Strip leaked protocol JSON from completions before behavioral compare.
  7. Re-enroll on a timer. Two mismatch days beat one.

Unlimited budget is spent on more cells, more goldens (CJK/code/emoji/vision), and cadence — not on a second tokenizer scanner or LLMmap plus Tosea plus LLM-Fingerprinter.

Misconfiguration vs visible Anthropic JSON/headers

Two extra false-positive modes that look like “wrong model” in the wild and are not.

Misconfiguration underperformance

KVV already splits official vs open-source wiring: --think-mode kimi sends {"thinking":{"type":"enabled"}}; --think-mode opensource sends chat_template_kwargs. Apply the official extra_body to a vLLM/SGLang lane and thinking stays off; OCRBench/DeepSWE collapse. Same for GLM --tool-call-parser glm47 / --reasoning-parser glm45, Qwen vs Llama chat templates, truncated max_tokens, and effort low vs max.

Capability drop with a matching tokenizer contract and matching one-token JSD is the misconfig signature. A swap usually breaks tokenizer and/or JSD first. Protocol outcome: misconfigured, not mismatch, until the official serve recipe has been replayed.

Visible Anthropic JSON/headers

modelprint net-headerdna records anthropic-ratelimit-requests-limit as ant-rl, plus id prefixes (msg_ vs chatcmpl- / gen-). Those families identify Cloudflare / Bedrock / Anthropic Messages / OpenAI-compat gateways. A Claude served through OpenAI-compat often still leaks Messages JSON (type: message, content: [{type: text}], stop_reason) or the model echoes that envelope in the completion because the wrapper stuffed it into the prompt.

False positives both ways: “Anthropic headers ⇒ this is Claude” when the gateway is only translating; “JSON in the answer ⇒ different model” when the weights are real and the wrapper is dirty. Strip protocol envelopes before JSD. Keep header/id-prefix rows in stack DNA, never in the model-identity verdict.
